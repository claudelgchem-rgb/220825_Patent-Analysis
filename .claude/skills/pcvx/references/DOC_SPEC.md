# 문서 규격 (A10)

## 최종 산출물 5종 (모두 필수)

| 번호 | 파일 | 경로 |
|---|---|---|
| 1 | 워드 보고서 | `<OUT>/PCVX_특허조사보고서_<주제>_<YYYYMMDD>.docx` |
| 2 | 발표자료 | `<OUT>/PCVX_특허조사보고서_<주제>_<YYYYMMDD>.pptx` |
| 3 | 특허 대장 | `<OUT>/PCVX_특허대장_<YYYYMMDD>.xlsx` |
| 4 | 근거·출처 대장 | `<OUT>/PCVX_근거대장_<YYYYMMDD>.md` |
| 5 | 감사 로그 | `<OUT>/PCVX_감사로그_<YYYYMMDD>.md` |

`<OUT>` 은 `pcvx/scripts/preflight.py` 가 결정해 `workspace/env.json` 의 `output_dir` 에 적어둔 경로다.
`/mnt/user-data/outputs/` 가 존재하거나 생성 가능하면 그 경로를, 불가능하면 저장소 안의 `outputs/` 를 쓴다.
모든 작업 파일은 `pcvx/workspace/` 아래에서 만들고, 완성본만 `<OUT>` 으로 복사한다.
`<주제>` 는 공백을 밑줄로 바꾸고 파일명에 못 쓰는 문자를 제거한 축약형(30자 이내)을 쓴다.

## 워드 보고서 구성

1. 표지 — 제목, 조사 주제, 작성 기준일(오늘 날짜), 검색 대상 데이터베이스 목록
2. 이 보고서를 읽는 법 (1쪽) — 특허 용어 기초 설명, 신뢰도 등급의 의미
3. 한눈에 보는 요약 — 핵심 발견 5가지, 신뢰도 등급 분포
4. 기술 분야 개관 (A6 결과) — 이 분야가 어떤 상태인지 서술형으로
5. 특허 상세 — 건별로 1~1.5쪽. 서지정보 표 → 청구항 원문 → 구성요소 분해표 → 초보자용 평문 해설 → 신뢰도 등급 및 근거
6. 종합 정리 — 기술 갈래별 묶음, 주요 출원인 동향
7. 이 조사의 한계 (`references/LIMITS.md` 원문 삽입)
8. 부록 — 검색식 전문, 출처 URL 목록(접속일 포함)

- 본문 12~20쪽, 한 문단 4~6문장.
- 등급 색상: 상 = `1E6B34`, 중 = `C05621`, 하 = `C0392B`.
- '하' 등급 30% 초과 시 표지 다음에 경고 문구를 넣는다(`references/GRADING.md` 문구 그대로).

## PPT 구성 (14~20장)

1. 표지 (주제 / 작성 기준일)
2. 목차
3. 핵심 요약 3장 — 한 장에 메시지 하나. 슬라이드 제목은 명사가 아니라 **문장형 결론**으로 작성
4. 기술 분야 개관 1~2장 (연도별 출원 추이 그래프 포함)
5. 주요 특허 카드 슬라이드 — 상위 5~8건, 한 장에 한 건 (번호·날짜·권리자·핵심 청구내용 3줄·신뢰도 등급 배지)
6. 특허 전체 목록 표 1~2장
7. 신뢰도 등급 분포 1장
8. 한계 및 다음 단계 1장

- 글꼴 크기 18pt 이상, 한 장당 텍스트 7줄 이내, 발표자 노트에 A9 본문 요약 삽입.
- 연도별 출원 추이는 네이티브 차트로 넣는다(python-pptx `add_chart`, 또는 pptxgenjs `addChart`).

## 엑셀 특허 대장 시트 구성

| 시트 | 내용 |
|---|---|
| `특허대장` | 레코드 1건 = 1행. 서지 전 항목 + 등급 열 |
| `청구항` | 건별 독립항 원문·구성요소 분해 |
| `신뢰도` | 항목 단위 등급·판정근거·출처·확인일 |
| `검색식` | A1 검색식 전문과 의도 |
| `출처` | URL·접속일·소스코드·신뢰도 |

- 글꼴 Arial, 머리행 고정, 자동 필터, 열 너비 조정.
- 빈 셀 금지. 값이 없으면 `[확보 실패]` 와 사유를 쓴다.

## 생성 도구 선택 (preflight 결과에 따름)

`workspace/env.json` 의 `doc_toolchain` 값을 따른다.

- `node` — `/mnt/skills/public/{docx,pptx}/SKILL.md` 를 먼저 읽고 docx-js / pptxgenjs 로 생성
- `python` — `python-docx` / `python-pptx` / `openpyxl` 로 생성 (`pcvx/scripts/build_*.py`)

두 경로 모두 생성 후 반드시 열어서 확인한다(G7). 확인은 `pcvx/scripts/inspect_outputs.py` 가
파일을 실제로 열어 수행한다.

`env.json` 의 `render_available` 이 `true` 면 LibreOffice 로 PDF 변환해 눈으로도 확인한다.
`false` 면 그 환경에서는 변환이 동작하지 않는다는 뜻이므로 시각 확인을 건너뛰고,
`render_note` 를 감사 로그에 기록한다.
