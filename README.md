# PCVX — 특허 서지·청구항 정리 + 독립 신뢰도 검증 하니스

**PCVX (Patent Claim & Verification eXplorer)** 는 특허 조사를 열두 개의 역할로 쪼개
순서대로 돌리고, 각 단계마다 기계 검사를 통과해야 다음으로 넘어가게 만든 다중 에이전트 하니스다.

핵심은 두 가지다.

1. **조사자와 검증자를 격리한다.** 신뢰도 검증 에이전트(A7)는 조사 에이전트의 추론 과정을
   넘겨받지 않는다. `[항목] [값] [출처 URL] [접속일]` 네 가지만 받아 백지 상태에서 원출처를
   직접 다시 연다. 검증자가 조사자의 논리에 오염되지 않게 하려는 것이다.
2. **미루기를 기계로 막는다.** "추후 확인", "TBD", 빈 표 셀 같은 것들은 사람이 눈으로 찾는 대신
   검사기가 실제로 문자열을 뒤져서 잡는다. 한 건이라도 나오면 해당 파트가 반려된다.

## 빠른 시작

```bash
python3 pcvx/scripts/preflight.py     # 오늘 날짜·출력 경로·문서 도구 확인
```

그다음 Claude Code 에서 `/pcvx` 를 부르거나, 특허 조사를 요청하면 된다.
조사 주제를 함께 주면 되묻지 않고 끝까지 완주한다. 주제가 없으면 딱 한 번 묻는다.

## 하니스가 성한지 먼저 확인하려면

```bash
python3 pcvx/scripts/selftest.py        # 표본 데이터로 파이프라인 전체를 돌린다
python3 pcvx/scripts/negative_test.py   # 일부러 어긴 입력을 게이트가 잡는지 본다
```

`selftest` 는 게이트 8개와 완료 조건 9개를 모두 통과하고 산출물 5종을 실제로 만든다.
`negative_test` 는 위반 11종을 주입해 게이트가 전부 반려하는지 확인한다.
둘 다 임시 디렉터리에서 돌며 실제 작업물을 건드리지 않는다.

## 구성

```
.claude/skills/pcvx/
  SKILL.md                  오케스트레이터 실행 절차
  references/
    RULES.md                3대 절대 규칙 (모든 에이전트 프롬프트 선두에 복사되는 원문)
    SCHEMA.md               에이전트 간 데이터 계약 (JSON 형식)
    SOURCES.md              데이터베이스 8곳·검색 URL·폴백 경로·문헌번호 표기 표준
    GRADING.md              신뢰도 상/중/하 판정 기준
    STYLE.md                초보자용 문체 규칙·용어 뜻풀이 표준
    DOC_SPEC.md             워드/PPT/엑셀 규격
    LIMITS.md               보고서에 원문 그대로 들어가는 한계 문단
    GATES.md                G1~G8 기계 판정 기준

.claude/agents/             하위 에이전트 11개 (A1~A11)
pcvx/scripts/               검사기와 문서 생성기
pcvx/workspace/             작업 중간 산출물 (JSON) — 커밋하지 않는다
```

## 에이전트 11개

| 에이전트 | 역할 | 게이트 |
|---|---|---|
| A1 검색식 설계 | 주제 분해, 분류코드, 검색식 6종 | G1 |
| A2 다중 검색 | 데이터베이스 8곳 최신순·계단식, 패밀리 단위 중복 제거 | G2 |
| A3 법적상태 | 우선일~만료일, 오늘 기준 법적 상태 | G3 |
| A4 서지정보 | 번호·날짜·권리자·분류, 국제 표준 표기 | G3 |
| A5 청구항 | 독립항 원문, 구성요소 분해, 평문 해설 | G3 |
| A6 기술 맥락 | 연도별 추이, 주요 출원인, 기술 갈래 | — |
| A7 신뢰도 검증 ★격리★ | 항목 단위 상/중/하 + 판정 근거 | G4 |
| A8 레드팀 | 누락·과대해석·최신성·번호 혼동 점검, 반려 | G5 |
| A9 보고서 | 초보자용 서술형 본문 | G6 |
| A10 문서 생성 | docx / pptx / xlsx / 근거 대장 | G7 |
| A11 감사 | 3대 규칙 체크리스트, 감사 로그 | G8 |

A8은 문제를 찾되 **직접 고치지 않는다.** 반려만 하고 수정은 해당 에이전트가 한다(권한 분리).

## 산출물 5종

| 파일 | 내용 |
|---|---|
| `PCVX_특허조사보고서_<주제>_<날짜>.docx` | 초보자용 서술형 본문 12~20쪽 |
| `PCVX_특허조사보고서_<주제>_<날짜>.pptx` | 발표용 14~20장 |
| `PCVX_특허대장_<날짜>.xlsx` | 시트 5개 (특허대장·청구항·신뢰도·검색식·출처) |
| `PCVX_근거대장_<날짜>.md` | 항목별 출처 URL·접속일·등급·정정 이력 |
| `PCVX_감사로그_<날짜>.md` | 3대 규칙 준수 여부, 확보 실패 경로 기록 |

출력 경로는 preflight 가 정한다. `/mnt/user-data/outputs/` 를 쓸 수 있으면 그곳을,
아니면 저장소 안의 `outputs/` 를 쓴다. `PCVX_OUTPUT` 환경변수로 덮어쓸 수 있다.

## 검사기

| 스크립트 | 하는 일 |
|---|---|
| `preflight.py` | 날짜·출력 경로·문서 도구·렌더 가능 여부를 실제로 시험 |
| `run_gates.py G1..G8 / all / checklist` | 게이트 판정과 완료 조건 체크리스트 |
| `validate_records.py` | 문헌번호 표기, 필수 필드, 등록 여부 구분, 확인일 |
| `validate_report.py` | 금지 표현, 약어 풀어쓰기, 빈 표 셀, '하' 등급 단정형 |
| `make_verify_input.py` | A7 격리 입력 생성 (조사 추론을 걷어낸다) |
| `inspect_outputs.py` | 산출 파일을 실제로 열어 빈 셀·빈 슬라이드·분량 검사 |
| `build_xlsx / build_docx / build_pptx / build_evidence` | 산출물 생성 |

### 금지 표현 검사의 허용 목록

`예정`, `확인 필요` 같은 문자열은 금지어지만, 지시서가 직접 요구한 정식 표현에는 예외를 둔다.
`존속기간 만료 예정일`(A3 필수 항목), `원문 확인이 필요하다`('하' 등급의 지정 서술 형식),
`전문가 검토가 필요합니다`(30% 초과 경고 문구) 등이다.
허용 목록은 `references/RULES.md` 와 `pcvx/scripts/common.py` 양쪽에 같은 내용으로 있다.

## 이 하니스가 하지 않는 것

이 도구는 특허의 존재와 청구 내용을 정리할 뿐, 특정 제품이나 공정이 그 특허를 침해하는지
판단하지 않는다. 사업상 실시 가능성(자유실시, Freedom to Operate) 판단이 필요하면
유료 상용 데이터베이스 전수 조사와 변리사·특허 전문가의 법률 검토를 별도로 받아야 한다.
전체 한계 문단은 `references/LIMITS.md` 에 있으며 모든 보고서에 원문 그대로 들어간다.
